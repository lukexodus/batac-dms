## Project-wide DDL conventions (C1 Part 1)

- Every table: `id UUID NOT NULL PRIMARY KEY DEFAULT gen_random_uuid()`.
- Every table: `city_id UUID NOT NULL DEFAULT '00000000-0000-4000-8000-000000000001'::uuid`
  (tenant sentinel; not a FK constraint).
- All temporal columns: TIMESTAMPTZ. Every mutable table: `created_at TIMESTAMPTZ NOT NULL
DEFAULT now()` and `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`.
- The `updated_at` column is kept current by the shared trigger function
  `public.fn_set_updated_at()` (already created by TASK-INFRA-006). Pattern per table:
  `CREATE TRIGGER trg_{tablename}_set_updated_at BEFORE UPDATE ON organization.{tablename}
FOR EACH ROW EXECUTE FUNCTION public.fn_set_updated_at();`
- Soft delete only: all tables carry `deleted_at TIMESTAMPTZ NULL` and `deleted_by UUID NULL`.
  No table may ever receive a SQL DELETE. DELETE is revoked at the PostgreSQL grant level by
  TASK-INFRA-006.
- No native PostgreSQL ENUMs in the organization schema: use `TEXT NOT NULL CHECK (column IN (...))`.
- No FOREIGN KEY constraints across schema boundaries. Cross-schema references are plain UUID
  columns with a comment: `-- logical FK → <schema>.<table>.<column> (cross-schema)`.
- Drizzle conventions: use `drizzle-orm/pg-core`, `pgSchema`, `pgTable`, `uuid`, `text`,
  `boolean`, `timestamp`, `date`, `jsonb`, `index`, `uniqueIndex` helpers.
  Schema file: `/packages/database/src/schema/organization.ts`.

### organization.assignments

```sql
-- is_primary flag: RESOLVED ADR-AUTH-011, 2026-06-26.
-- At most one active primary assignment per employee enforced by partial unique index.
-- The application layer (ORG service) must maintain this invariant atomically:
-- unset all other is_primary = true rows for the same employee_id BEFORE setting the new one,
-- within a single transaction.
CREATE TABLE organization.assignments (
    id          UUID        NOT NULL PRIMARY KEY DEFAULT gen_random_uuid(),
    city_id     UUID        NOT NULL DEFAULT '00000000-0000-4000-8000-000000000001'::uuid,
    employee_id UUID        NOT NULL REFERENCES organization.employees(id),
    position_id UUID        NOT NULL REFERENCES organization.positions(id),
    office_id   UUID        NOT NULL REFERENCES organization.offices(id),
    start_date  DATE        NOT NULL,
    end_date    DATE        NULL,
    is_active   BOOLEAN     NOT NULL DEFAULT true,
    is_primary  BOOLEAN     NOT NULL DEFAULT false,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    deleted_at  TIMESTAMPTZ NULL,
    deleted_by  UUID        NULL,
    CONSTRAINT ck_assignments_dates CHECK (end_date IS NULL OR end_date >= start_date)
);
CREATE TRIGGER trg_assignments_set_updated_at
    BEFORE UPDATE ON organization.assignments
    FOR EACH ROW EXECUTE FUNCTION public.fn_set_updated_at();
CREATE INDEX idx_assignments_employee ON organization.assignments(employee_id);
CREATE INDEX idx_assignments_position ON organization.assignments(position_id);
CREATE INDEX idx_assignments_office   ON organization.assignments(office_id);
-- DB-level safety net for one-primary-per-employee invariant.
CREATE UNIQUE INDEX uq_assignments_one_primary_per_employee
    ON organization.assignments (employee_id)
    WHERE is_primary = true AND is_active = true AND deleted_at IS NULL;
```

## organization.cross_office_grants — security config table [Resolved — B5 §6.5 / ADR-AUTH-009]

This table was a spec gap in the original pass load list (C1 §organization omitted it). It is
now confirmed from B5 §6.5 and ADR-AUTH-009. Include it in this migration.

**Convention deviations — intentional:** `cross_office_grants` is a security configuration
table, not a user-managed runtime data table. It intentionally omits: `city_id`, `updated_at`,
`deleted_at`, `deleted_by`, and the `fn_set_updated_at()` trigger. Rows are replaced (DELETE

- INSERT), not soft-deleted. The Drizzle schema file must NOT add these columns to this table.

**Cross-schema FK exception:** The `role_id` column carries a real PostgreSQL FK to
`iam.roles(id)`. This is the sole authorized exception to the project-wide "no FK constraints
across schema boundaries" rule. Authorized by ADR-AUTH-009 §Consequences; the rationale is
that this table's entire purpose is to bind organization-level access rules to IAM roles, making
the referential constraint appropriate here.

```sql
-- organization.cross_office_grants
-- Intentionally no city_id / updated_at / deleted_at / deleted_by (security config table).
-- Cross-schema FK to iam.roles(id) is an authorized exception per ADR-AUTH-009.
CREATE TABLE organization.cross_office_grants (
    id             UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    role_id        UUID        NOT NULL REFERENCES iam.roles(id),
    office_scope   TEXT        NOT NULL CHECK (office_scope IN ('all')),
    access_level   TEXT        NOT NULL CHECK (access_level IN ('metadata_only', 'full')),
    resource_types TEXT[]      NOT NULL,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
-- No updated_at trigger: this table has no updated_at column.
-- Seed data (4 rows from B5 §5.6) inserted by TASK-IAM-013.
```

The `has_cross_office_read_grant()` SQL function (confirmed — B5 §6.5 / ADR-AUTH-009).
Include in the migration after the table DDL:

```sql
CREATE OR REPLACE FUNCTION has_cross_office_read_grant(
    p_user_id  UUID,
    p_office_id UUID
) RETURNS BOOLEAN AS $$
    SELECT EXISTS (
        SELECT 1
        FROM organization.cross_office_grants g
        JOIN iam.role_assignments ra ON ra.role_id = g.role_id
        WHERE ra.user_id = p_user_id
          AND ra.revoked_at IS NULL
          AND (g.office_scope = 'all')
          -- specific-office-scope branch intentionally omitted (ADR-AUTH-009):
          -- all four seeded roles use office_scope = 'all'. A future role needing
          -- per-office granularity requires a schema change + function update.
    );
$$ LANGUAGE sql STABLE;
```

**Notes on function limitations (ADR-AUTH-009 §Consequences, not resolved here):**

- The function only handles `office_scope = 'all'`. This covers all four B5 §5.6 roles.
- `access_level = 'metadata_only'` vs `'full'` is stored but NOT enforced by this function;
  it only answers "can this user read across offices at all." The calling RLS policy must add
  a second condition to enforce the metadata/full distinction (Documents module migration work).
- This function cross-joins `iam.role_assignments`. Both schemas exist when this migration
  runs (IAM migration is a prerequisite via TASK-IAM-001 dependency chain).

## setPrimaryAssignment invariant (ADR-AUTH-011)

The one-primary-per-employee rule must be maintained atomically. Implement as a transaction:

```typescript
async function setPrimaryAssignment(
  employeeId: string,
  targetAssignmentId: string,
  trx: DbTransaction,
): Promise<void> {
  // Step 1: unset all current primary assignments for this employee
  await trx
    .update(assignments)
    .set({ isPrimary: false, updatedAt: new Date() })
    .where(
      and(
        eq(assignments.employeeId, employeeId),
        eq(assignments.isPrimary, true),
        isNull(assignments.deletedAt),
      ),
    );
  // Step 2: set the new primary
  await trx
    .update(assignments)
    .set({ isPrimary: true, updatedAt: new Date() })
    .where(eq(assignments.id, targetAssignmentId));
}
```

Callers must supply a transaction — this function must never open its own.

import type { FastifyInstance } from 'fastify';
import { createOrgRepository } from './organization.repository';
import { createOrgService } from './organization.service';
import { createDelegationService } from './delegation.service';

async function organizationPlugin(fastify: FastifyInstance): Promise<void> {
  const orgRepository = createOrgRepository(fastify.db);
  const organizationService = createOrgService({ db: fastify.db, repository: orgRepository });
  const delegationService = createDelegationService({

    'orgTrpcRouter',
    createOrgRouter({
      policyEvaluator: fastify.policyEvaluator,
      organizationService,
